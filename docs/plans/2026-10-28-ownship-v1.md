# ownship v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first end-to-end loop: a Claude Code or Codex turn ends, ownship snapshots the diff, asks the user's own agent for 0 to 3 evidence-backed cards, and serves them for review with FSRS on the phone and the desktop.

**Architecture:** One Node package. A daemon (started on demand) watches the agents' session logs through one reader per agent, snapshots the git working tree per turn, queues turns, runs the generator command, validates cards, stores everything in SQLite and serves a Vue review app over HTTP with token auth. The CLI installs hooks, starts the daemon and pairs the phone.

**Tech Stack:** TypeScript, Node with `node:sqlite`, `ts-fsrs`, Vue 3 + Vite + vue-i18n, Vitest + @vue/test-utils + happy-dom, ESLint + Prettier, lefthook, pnpm.

**Spec:** [docs/specs/2026-10-28-ownship-v1-design.md](../specs/2026-10-28-ownship-v1-design.md). Decisions: [docs/adr/](../adr/). Formats: [docs/research/agent-capture-survey.md](../research/agent-capture-survey.md). Read all three before Task 1.

## Global constraints

- Package and command `ownship`; install `npx ownship init`. pnpm only; one package, no workspace.
- Runtime: Node with built-in `node:sqlite` and no native modules. Minimum Node version is pinned in Task 1 from the official Node docs and enforced by `engines` and by `ownship init`.
- Every new dependency gets an entry in `docs/research/versions.md` (version, official source, why) and respects pnpm `minimumReleaseAge` of 1 day.
- Everything in the repo in English. No literal UI copy: `app/i18n/en.json` and `app/i18n/es.json` change together.
- Conventional Commits; never a `Co-Authored-By` trailer for an AI or a "Generated with" line.
- Home directory `~/.ownship/`, overridable with `OWNSHIP_HOME` (all tests use a temp `OWNSHIP_HOME`): `ownship.db`, `config.json`, `token`, `daemon.json`, `knowledge/<repo>/`.
- Values from the spec: 0 to 3 cards per turn; 10 new cards per local calendar day by default; queue newest first; turns expire after 7 days; 2 or 3 key ideas per defend card; 3 or 4 options with exactly one correct; two FSRS ratings (Again, Good); daemon binds `127.0.0.1`; `OWNSHIP_GENERATING=1` on every generator run; event schema `ownship.turn/1`; one retry on invalid generator output.
- Readers fail closed: unknown format or version means skip the turn and log it instead of guessing.
- Never touch the user's git index, stash, branches or working tree; never read agent auth files.

## Review focus

1. **A huge turn** (thousands of changed lines, a generated migration, a vendored folder): the generator input is truncated to a budget with a marker, never an error or a giant prompt. Test in Task 7.
2. **A repo with no commits yet, a detached HEAD or a merge in progress**: snapshots and diffs still work (empty-tree base when `HEAD` is missing). Test in Task 3.
3. **The generator is missing, logged out, slow or prints garbage**: the turn stays queued with a recorded error, after a timeout; the daemon never crashes. Test in Task 8.
4. **A log line half-written when read, a log file rewritten or shorter than the saved offset, or the hook and the watcher both reporting the same turn**: partial lines are left for the next read, a shrunken file is reread from 0, and turns are deduplicated by `(agent, sessionId, turnId)`. Test in Task 6.
5. **The phone retries an answer on a flaky network**: answers carry a client `reviewId` and a repeat is a no-op, so FSRS is never applied twice. Test in Task 13.

### Task 6: Capture loop: watch, catch up, snapshot, merge, deduplicate

**Files:**

- Create: `src/capture/capture.ts`
- Test: `test/capture/capture.test.ts`

**Interfaces:**

- Consumes: `Reader` (Tasks 4 and 5), `repoIdentity`, `snapshot`, `baseTree`, `diffTrees` (Task 3), `openDb` (Task 2), `loadConfig` (Task 2).
- Produces:
  - `type TurnRow = { id: number; agent: AgentName; sessionId: string; turnId: string; worktree: string; commonDir: string; slug: string; endedAt: string; status: RawTurn["status"]; state: "queued" | "generated" | "expired" | "skipped" | "failed"; attempts: number; lastError: string | null; event: TurnEvent }` and `getTurn(db, id: number): TurnRow | null`.
  - `processFile(db, reader: Reader, file: string, now: Date): Promise<number>`: reads from the saved offset (from 0 when the file is now shorter than the offset), turns completed turns into `TurnEvent`s, stores them as `queued`, saves the new offset, returns how many turns were stored.
  - `catchUp(db, readers: Reader[], now: Date): Promise<void>`: `processFile` over every file modified since its saved offset was written.
  - `watch(db, readers: Reader[]): () => void`: `fs.watch(root, { recursive: true })`, debounced 2 s per file, calling `processFile`; returns a stop function.
- Rules inside `processFile`: drop turns whose origin is not `interactive`, whose status is not `completed`, whose `cwd` is outside git or whose `commonDir` matches `config.exclude`. A turn is **live** when `now - ts.end <= 120 s`: it gets its own snapshot immediately, and its diff is `previous snapshot of that worktree (or baseTree) → new snapshot`. Consecutive **missed** turns of one worktree within a read are merged into one event (`merged: true`, prompts joined in order, `messages` concatenated, `turnId` of the last one) with one diff from the previous snapshot to a new one. Insert with `INSERT OR IGNORE` on `(agent, session_id, turn_id)`.

- [ ] **Step 1: Write failing tests** with a fake reader and a temp repo:
  - `a live turn gets its own diff`: edit, turn ends, process; event has the edit only. A second edit and turn: the second event has only the second edit.
  - `missed turns of one worktree merge into one event`: two turns with `ts.end` 1 h before `now`; one stored event with `merged === true` and both prompts.
  - `the same turn reported twice is stored once`: call `processFile` twice over the same bytes, and once more after a doorbell-style reread from 0; one row.
  - `a file shorter than its saved offset is reread from the start`.
  - `headless, interrupted, excluded and non-git turns are not stored`.
- [ ] **Step 2: Run** `pnpm vitest run test/capture/capture.test.ts`. Expected: FAIL.

    - `GET /api/session?limit=5` → `{ cards: SessionCard[] }`, cards due now first, then new cards, where `type SessionCard = CardDraft & { id: number; repo: string; endedAt: string }` (`repo` is the turn's slug); the client reveals answers locally (`// ponytail: answers are sent with the card; this is a self-study tool`).
